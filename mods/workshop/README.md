# 装备工坊 · Equipment Workshop 1.4.4

装备耐久、修理、强化、分解与魔法箭合并为一个 MO2 模组、一个 SKSE DLL：`EquipmentWorkshop.dll`。目标 Skyrim SE 1.5.97、SKSE、Address Library；界面优先使用 Meridian UI，未启用时回退到 PrismaUI。两份原有源码作为独立模块编译进同一个目标，不再同时运行 DurabilityManager.dll 和 MagicArrows.dll。

## 界面

使用魔法箭的深蓝／青绿色风格、左侧导航和轻微透明背景（主体约 82–85% 不透明，文字保持不透明）。装备页支持搜索、武器／护甲／衣物／已装备筛选，保留修复、强化、状态与 HUD。魔法箭作为一级栏目，内部提供「箭矢装备」「制作魔法箭」「制作普通箭」。装备列表、队列、同屏配方台与成品预览均由 React 渲染，运行时只有一个浏览器视图和一个外层导航，栏目切换不改变页面地址或交接焦点。设置分为「通用设置」「装备养护」「魔法箭」三页；通用设置包含工坊快捷键、字号、透明度和音效。

Shift+A 打开整个装备工坊（1.0.3 起）；1.1.0 起统一版只注册这一个键盘入口，原 Shift+W 不再单独响应。两个旧能力入口保留，魔法箭能力会打开统一工坊的魔法箭栏目。自定义主快捷键读取 DurabilityManager.ini；MagicArrows.ini 继续保存随从设置。

## 分解回收

靠近现有支持的锻造设施（600 游戏单位）打开「分解回收」，选择背包装备后自动显示回收材料，再确认分解一件。

- 每次确认使用一次性凭据；原生端重新检查设施距离、库存、保护状态、回收材料和装备状态，双击不重复分解。
- 可分解已装备的独立实例，先安全卸下；卸下失败时保留装备。移除成功并确认数量减少后才发放材料。
- 任务、唯一／神器、召唤武器不允许分解；独立实例的共享堆叠需先拆分。完全普通、没有附加实例的堆叠每次回收一件。混有附加实例的同名普通堆叠拒绝模糊删除，需先装备再卸下要分解的那一件。
- 有制作配方时按每件产量折算后回收约一半材料（每件至少有一份投入时，该材料最低回收一份），忽略金币、装备和物品自身。强化配方不作为制作回收依据。
- 没有制作配方时，衣物回收一份皮革条，其他装备回收一块铁锭。有配方但折算不到一份材料时不能回收。
- 分解会永久失去该件装备及其附魔、强化。确认清单不收取额外金币。

## 旧存档兼容

必须保留 `MagicArrows.esp`、`DurabilityManager.esp` 的名称与 FormID；安装包包含原文件。这两份 ESP 是旧箭矢和面板能力的数据载体，不是两个运行 DLL。直接合并／改名 ESP 会破坏旧存档引用，因此本版不改它们。

统一 DLL 继续使用耐久度的 SKSE UID `0x4455524D`，一次 save/load/revert 回调同时处理耐久度和箭矢队列。旧箭矢 UID `0x4D415151` 的队列由旧 `.skse` 文件只读导入，路径遵循游戏 `sLocalSavePath:General`，ID 通过 SKSE ResolveFormID 重定位；新格式队列记录优先于旧格式。下次正常保存时写入统一记录，不直接改写旧存档文件。箭矢的运行时绑定继续使用原来的游戏原生记录。

旧队列文件解析遵循 [SKSE 的 Serialization.cpp 文件结构与保存路径](https://github.com/ianpatt/skse64/blob/master/skse64/Serialization.cpp)。保留旧存档副本供回退；统一版保存后不要直接降级到旧的两个 DLL。

## 安装

1. 退出游戏。在 MO2 安装 `EquipmentWorkshop-1.4.4.zip` 为一个新模组。
2. 统一版主快捷键为 Shift+A；迁移旧配置后，将 DurabilityManager.ini 的 [Hotkey] 设置为 Key=A、Shift=true、Ctrl=false、Alt=false。分解快捷键仍为 Shift+D。将旧模组中定制过的 `DurabilityManager.ini`、`DurabilityManager.rules.json` 和 `MagicArrows.ini` 复制到新模组同一路径。
3. 禁用旧的耐久度模组和魔法箭模组，启用装备工坊。保持两个原 ESP 启用及原有排序。不要同时加载旧 DLL。
4. 启动游戏，用现有存档验证，确认后另存新档。旧存档和旧模组文件可保留作为回退。

打包脚本只生成安装包；本地更新另行备份后覆盖界面与 DLL，并保留已有 INI、规则文件及存档。

## 直接分解快捷键（1.0.1）

在「工坊设置」点击「录入分解快捷键」后按下组合键，可设置 A–Z、F1–F12 或 Delete，搭配 Ctrl / Shift / Alt，Esc 取消。分解页显示当前按键和启用开关。默认 Shift+D，保存后立即生效并写入 DurabilityManager.ini 的 [DismantleHotkey]。仅在面板获得焦点、分解页打开且靠近锻造设施时有效；搜索、编辑设置、任务及唯一装备均不会触发。每次按下只分解当前选中一件，跳过材料预览与确认；按住不会连发。保留库存、实例及材料校验。

## 药水充能（1.0.2）

魔法箭制作允许使用背包中功效匹配的药水和毒药，包括自制成品。材料区按药水、毒药、原材料排序，同类按每瓶／份充能从高到低排列；玩家明确选择后才加入消耗清单，可与原材料混用，确认制作才消耗。

成品药水读取所有实际效果，不要求发现功效；原材料仍只读取已发现效果。沿用现有对应关系：抗火／抗冰／抗电／抗毒匹配对应元素，生命匹配血／光，耐力匹配风／水／土，魔法匹配暗／灵／奥术。只接受对应 ValueModifier 或 PeakValueModifier 效果，多效果取最高匹配充能，不累加、不按名称猜测。任务物品、食物和不匹配效果不参与。

每瓶与原材料共用效力公式：ceil(min(100, abs(magnitude) * sqrt(clamp(duration / 30, 1, 4))))，最高 100 点。药水效力更强或持续更久可提供更多充能；不额外乘以炼金术，避免对自制药水重复加成。炼金术仍降低每支箭所需充能。药水仅作为资源消耗，不触发饮用效果，不替代金币和角色法力支出。

已验证原生规则、混合充能与前端排序；游戏内预制／自制药水识别和实际扣除仍待验收。

1.0.3：主入口默认改为 Shift+A；在魔法箭子页也可使用主快捷键关闭工坊。原 Shift+W 兼容入口保留，分解快捷键仍为 Shift+D。

1.0.4：武器耐久归零并成功自动分解后，显示游戏原生通知，包含实际武器名称、损坏分解说明与回收材料；工坊 HUD 同步显示，默认展示至少 5 秒（仍可能被后续 HUD 消息替换）。保护性损坏或移除失败时不显示分解成功通知。

## 环境与移动磨损（1.0.5）

玩家遭受敌对／有害魔法、法杖、卷轴和游戏报告的陷阱命中时，也会按身体覆盖权重抽取一件穿戴装备磨损。魔法与陷阱默认分别乘以 1.0，沿用护甲每次 1.0、衣物 1.25 的基础值；重击倍率仍沿用现有规则。盾牌只承接可格挡的物理命中，魔法命中抽取身上护具。治疗、增益与自己发出的效果跳过。

同一攻击者／陷阱引用与来源记录的连续魔法／陷阱命中，每秒最多结算一次。物理攻击保留原有逐次结算。此处依据命中事件，不要求生命实际下降；免疫或护盾挡住的命中仍可能磨损。纯脚本 DamageAV 直接扣血、没有 TESHitEvent 的特殊陷阱暂不覆盖；持续效果后续仅扣血而不再次发出命中事件时也不额外磨损。

移动由玩家脚步事件采样水平距离，累计至少 1,000 游戏单位后结算：鞋靴 0.02、身体装备 0.005 / 1,000 单位，两类均受耐磨强化减免。没有鞋靴就不把其损耗转移到其他装备，武器、首饰和背包库存不因移动磨损；同时占用鞋靴及身体槽位的装备只按鞋靴计算一次。骑马、游泳、飞行、坐下、空中、暂停时不计。读档、换装、长时间没有脚步、跨单元和明显位置跳变会清除距离基线；因此短段移动可能不足一次结算。自定义移动动画仍需发出原生脚步事件。

新选项位于 DurabilityManager.ini 的 [Wear]：MagicHitWearMultiplier、TrapHitWearMultiplier、ContinuousHitIntervalSeconds、MovementBootWearPer1000Units、MovementBodyWearPer1000Units。倍率或移动数值设为 0 可分别关闭。缺少字段时使用上述默认值，面板保存配置会保留并写出这些数值。工坊装备详情新增每 1,000 单位的移动磨损提示。

原生分类／限频／移动距离规则测试与 37 项前端回归通过，统一 DLL 编译通过；游戏中的法术、陷阱与实际步行采样仍待验收。


## 1.0.6 · 连续分解与菜单切换

- 原生端确认分解成功后返回物品 ID 与一次性回执；前端按分解前的筛选顺序选中上一条仍存在的物品，并恢复焦点和滚动位置。没有上一条时选择下一条，空列表清空选择。堆叠每次仍只分解一件。
- 装备列表支持上下方向键；游戏使用原生键盘事件桥接，浏览器预览使用 DOM 事件，避免双重触发。输入框、强化页和按键录入期间不改变选中。
- 分解快捷键在设置页直接按键录入并自动写入 INI；可用 Shift/Ctrl/Alt + 字母/F1–F12/Delete，与面板开关键冲突时继续等待重新录入。分解页只显示按键与开关。
- 两个工坊视图关闭后等待暂停和焦点释放，再打开目标视图；跨存档请求失效，超时给出提示。修复浏览器预览的魔法箭往返导航。

验证：原生 Release 编译、40 项装备页面测试通过；浏览器实测方向键、分解后上一条与焦点、新组合键录入、开关以及魔法箭往返。游戏实际焦点交接仍需重新启动后验收。

## 1.2.0 · 网格库存与步骤式制作

- 魔法箭顶部直接提供「箭矢装备／制作魔法箭／制作普通箭」三个 Tab，保留各自选择状态。
- 使用队列仍位于库存顶部，箭矢改为网格卡片；点击选中，详情中装备或加入队列。
- 魔法箭制作分为法术、箭矢、材料充能三步，一次显示一个选择区域。步骤条可返回已解锁步骤，兼容选择会保留。
- 箭矢与材料统一使用滑块＋数字输入框，0 表示不用。基材总数上限 100，单项受库存限制；材料最多使用 10,000 份。更换法术或库存刷新时移除不兼容项并裁剪超出库存的数量。
- 右侧固定显示每支金币／法力／充能，金币和法力进度条将制作后剩余与本次消耗分为青绿、暖色两段，资源不足显示缺口。清单展示实际基材与材料消耗，确认按钮固定在底部。
- 药水优先排列，每种材料可点击「补足」按库存补足所需充能，也可手动调整并查看多余充能。费用仍由原生端核对后才能确认。
- 提取 QuantitySlider、ResourceMeter 和数量规则模块；数字输入和滑块共用一份数量状态，避免失焦时旧输入覆盖新选择。

验证：51 项前端测试通过，覆盖库存限制、100 支上限、零数量、法术兼容、部分产量清单和资源分段；浏览器验证网格、三个入口、逐步选择、滑块联动、返回保留、资源不足与确认限制。原生扣料和存档逻辑保持原有实现，游戏内实测仍需启动后验收。

## 1.4.2 · 魔法箭制作音效

## 1.4.3 · 装备耐久常显

- 当前装备的实体武器常显，收起后仍显示；双持按左右手与实例区分，召唤武器不参与。
- 已穿戴且耐久严格低于设置阈值的其他装备常显，卸下或修复后自动移除。
- 每 0.5 秒在游戏主线程检查，内容变化时更新；打开工坊、暂停、对话、读档和死亡时隐藏。
- 常显列表与损坏、低耐久临时通知分开；原显示时长仅控制临时提示，预警开关仅控制一次性弹出提示。
- 半透明黑底、统一无衬线数字，耐久条使用亮色完整边框标示上限。


## 1.4.4 · 常显 HUD 启动握手修复

- 修复界面首次加载早于原生桥接函数注入时，ready 消息丢失导致常显一直不启动的问题。
- 原生定时更新会重试握手，收到页面真实回应后才发送装备状态；不抢焦点、不打开工坊。
- 日志新增等待握手、游戏状态允许显示、初始装备数量，便于区分初始化和装备筛选问题。
