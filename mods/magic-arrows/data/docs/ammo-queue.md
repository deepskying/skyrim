# 0.9.8 玩家箭矢使用队列

## 使用

在装备页的箭矢卡片下点「＋ 加入队列」，按添加顺序排队。队列卡片支持拖拽、前移/后移、移除，显示序号、库存徽章、当前装备和缺货状态。最多 64 种，支持普通弓箭、魔法箭和外观试作箭；本版不处理弩矢或随从的独立队列。

「从队首开始」打开自动接续并装备第一种有库存的箭。「自动接续」开关也可以单独启用：当前装备在队列内时，从它的位置接续，不立即改动装备。加入、移除、排序均不消耗或转移物品。

当前一种用尽后，只向后寻找下一种可用箭，跳过零库存/失效项，不绕回队首。全部用尽后本轮结束，后续沿用游戏选箭行为；补充库存后可以再点「从队首开始」。暂缺库存的条目保留在队列中。原生 API 拒绝重复、非整数、超长队列，以及不在背包中的新条目。

## 保存与迁移

顺序和自动接续开关保存在该角色正常保存时生成的 SKSE 附属存档。读取时通过 ResolveFormID 恢复普通和轻量插件引用；已删除来源无法解析的条目被丢弃。新游戏/载入其他存档先清空旧角色队列。没有附属队列记录的旧档默认空队列、关闭自动接续。

队列跟随 0.9.7 的法术箭主身份归并：读档和打开面板整理库存后，对旧别名映射至主身份，并去重保留第一次出现的顺序。队列不会回收或重排 ESP 的 AMMO/FLST 编号。

## 自动装备

延用已有 PlayerCharacter 更新回调，每 250 ms 最多安排一次 SKSE 主线程检查；关闭队列/暂停/面板焦点/死亡/未载入 3D/非弓武器时不检查或不切换。只在队列有效且持弓时获取一次库存快照；不修改原生射击和箭矢扣除函数。

追踪上次使用的箭及正库存，优先识别这组库存耗尽，即使原版已选了其他箭仍能选择队列下一项。没有耗尽时的手动换箭被尊重；选中队列中的箭会成为新的接续位置，选到队列外则暂停追踪。

切换仍通过既有延迟装备：至少两次更新和 250 ms、解除暂停后再提交一次，使用 GetCurrentAmmo 确认。自动请求增加存档代次、队列修订、武器和当前装备检查；期间读档、停用/编辑队列、手动改变装备会取消。超时停止当前请求，不重复刷装备。因为采用轮询和延迟提交，切换可能有约半秒延迟；高速射击和第三方自动换箭的组合必须实测，不能保证它们不会抢先发射原生自动选中的箭。

## 验证

- ammo-queue-test：耗尽后原生已换箭、跳过空库存、逐项向后不循环、手动选择、排序改变后续位置、读档重置、只调度一次、保存记录长度与开关校验。
- ammo-queue-test.cjs：拖拽排序算法与前后按钮共用逻辑，添加去重、移除、开关、容量上限、未连接时禁用。
- 本地浏览器：实际点击添加两项，实际鼠标拖拽交换顺序，从队首开始后预览装备高亮和开关正确。
- 待游戏：每项仅留一支连续射击、原生抢先换箭时接管、持弓/切近战、暂停/读档/死亡中断、64 项和缺货跳过、保存退出重进的顺序恢复。

网页预览不会修改游戏库存或存档，离线测试和编译不能替代实机验收。
