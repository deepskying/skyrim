# 1.0.0 魔法箭排队制作

在附魔台附近确认制作后，订单进入队列并继续在后台推进。制作页（统一工坊为「魔法箭 → 制作」，独立面板为「制作」）按同一套原生规则工作。

## 流程

1. 选择法术、基材箭矢数量与匹配的充能材料，原生端重算清单并返回一次性报价；任意输入、库存、功效或技能变化都会让报价失效，需要重新核对。
2. 点「开始制作」发送 `orderStart`，一次性扣除金币、基材与充能材料，订单进入队列并写入附属存档。此时不需要持有足够法力。
3. 插件按当前法力逐支产出，每支发一条游戏原生通知（与分解提示同一通道），成品直接进背包。法力不足时等待回复，这不算暂停。
4. 点击后即可离开附魔台、关闭工坊。队列在游戏中继续推进。

队列容量：每个法术最多 10000 支，同一法术的多批订单合并为一条条目并保留它在队列中的位置；不同法术按先来后到排列，同一时刻只推进队首的一条。单批输入合计同样最多 10000 支，每个输入框上限 999 支。面板在确认前用同一上限拦截，原生端再次校验。

## 暂停

按优先级判定，命中第一条即停止推进：

1. 载入中（Loading Menu／Main Menu）
2. 角色死亡
3. 工坊面板打开、界面持有焦点或尚未读档完成
4. 战斗中（`SKSE/Plugins/MagicArrows.ini` 的 `[Crafting] PauseInCombat`，默认 1；设为 0 可关闭）

等待法力回复、潜行、等待／坐下的施法暂停都不算暂停。队列只在游戏线程推进，每次最多处理一支，未装备请求优先。

## 中止与退款

法术失效、来源模组缺失或存档记录无法解析时，条目按未完成数量退还金币、基材与充能材料，并给出提示，不提供取消入口。已完成的支数不退。退款按选择顺序从各类基材尾部、并将材料按每支充能需求从清单前部折算整件返还。

## 存档

队列写入与箭矢使用队列相同的 SKSE 附属存档唯一 ID，记录类型 `0x4f524452`（"ORDR"），版本 1。条目保存法术、成品箭矢身份、进度、每支法力／充能／金币与锁定的基材／材料清单；读取通过 `ResolveFormID` 恢复，无法解析的法术或箭矢条目按已烘焙的完成量退款后丢弃。读档后队列继续推进，不新增 ESP 记录。

## HUD 与面板

统一工坊的左下角状态栏显示「制作队列」：每个排队法术一个菱形，外框从顶部顺时针表示剩余比例，菱形内是剩余支数（满千按 K 缩写），下方是成品名，边框沿用十二种箭矢外观族；暂停时标题行显示原因。屏幕较矮时只显示前几种法术，其余以「+N」计数。独立 `MagicArrows.dll` 在制作页列出同样的条目与暂停原因。

## 验证

- craft-order-test：容量上限与合并位置、逐支进度、退款算术、余量标注、暂停优先级、附属存档往返与解析失败丢弃。
- craft-order-hud.test.mjs：HUD 快照校验、菱形比例与配色、暂停文案、空队列与超长队列折叠、原生接线。
- 原生 DLL 编译（统一与独立两套）、前端类型检查与打包校验。
- 待实机：逐支产出的通知节奏与速度、法力恢复期间的推进、读档续做、退款提示以及菱形在真实分辨率下的排布。

离线测试和编译不能替代实机验收。
