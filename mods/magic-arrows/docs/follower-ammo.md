# 随从魔法箭消耗 — 0.8.0

默认按射击数量消耗本模组的运行时封存箭和旧版固定适配箭。以 Actor::IsPlayerTeammate 识别队友；未设置该标记的特殊随从框架角色仍沿用游戏规则。玩家、普通箭、试作箭及其他模组魔法箭不进入补扣逻辑。随从不需要学习原法术，命中执行仍使用此前的实际射手路径。

## 本地引擎核对

只读分析 Skyrim SE 1.5.97，Address Library 与 capstone 输出保存在 build/npc-use-ammo-full.asm.txt 和 build/ammo-cache.asm.txt，不进入发行包。

- Actor 虚表 0xD2 对应 UseAmmo，ID 37596，0x140624860。PlayerCharacter 有独立实现 ID 40240，本插件不修改玩家虚表。
- Actor 实现检查武器的 NPCsUseAmmo 等标志，以及角色条件，某些分支跳过扣除。消耗发生在 UseAmmo 调用阶段，非命中事件。
- 参数虽然声明 uint32，原实现对其作有符号检查；负值使用 MiddleHighProcessData +0x310 的缓存发射数量，不能简单把 -1 当一支。
- 返回值为剩余装备弹药数，不能返回本次发射数。装备弹药缓存通过 AIProcess +0x08 → MiddleHighProcessData +0x268 取得，是 InventoryEntryData；ID 15766/15790 读写其 +0x10 countDelta。

## 实现

保留并调用 Actor 虚表原有回调。仅对开启功能、绑定已恢复、队友、普通弓、可用的本模组法术箭及匹配的装备缓存进行核算，任务箭不进入补扣路径。分别读取调用前后库存：应消耗数为 min(发射数, 调用前库存)，补扣为 max(0, 应消耗数－已扣除数)，且不超过当前库存。

原调用已经扣足时不再扣；扣得更多时不退款。原调用返回零但调用前仍有库存时不额外扣除，避免给失败请求收费。回调期间加入库存、其他模组延迟退款或绕过 UseAmmo 的自定义发射不能凭这两个快照完全判定，仍需实测。

补扣通过原生 RemoveItem 完成，随后重新取缓存同步剩余量，不保存跨库存变更的 InventoryEntryData 指针。耗尽后以句柄和读档代次排队清理装备，执行前再次检查当前箭和库存，避免移除新补充或新换上的箭。角色 AI 后续如何选择普通箭由原游戏或随从框架处理。线程局部重入保护防止回调递归补扣。

## 设置与验证

设置页“随从魔法箭消耗”开关写入 MagicArrows.ini 的 [Followers] ConsumeMagicArrows=1/0，缺省 1。仅写这个键，保留快捷键和能力设置；写入成功才更新内存。关闭代表沿用游戏/其他模组规则，不强制无限。

已通过编译、消耗规划测试（已扣、未扣、部分连射、最后一支、零库存、负值哨兵、大数边界），浏览器模拟开关往返，Windows INI 临时文件写入/读取及其他段落保留验证。原 586 个非头部 ESP 记录不变。

未游戏验证：实际 NPC 调用路径、射空、多重射击、最后一支后的换装、同其他箭矢消耗模组的组合、随从框架标记、友伤和法术伤害。测试通过不能证明这些游戏行为已经正确。
