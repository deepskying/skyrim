# 强化规则（v0.1.33 / schemaVersion 1）

## 附魔兼容性缓存

v0.1.33 将同一基础装备的附魔兼容结果短暂缓存，减少装备列表、资格检查和抽卡中的重复扫描。缓存最长保留 5 秒，命中不会延长有效期；装备关键词或武器类别变化时立即重新计算。最多保存 512 种基础装备、262144 个签名与候选 FormID，超限时淘汰最久未使用的条目。读档、新游戏、序列化重置及规则 / 候选池重建都会清空缓存，不写入存档。

同款装备可以共享兼容候选，但各自当前附魔仍实时排除。任务 / 唯一保护、是否穿戴、材料是否足够也仍按实例实时检查。强化付款前和替换附魔时保持完整校验，不会凭缓存跳过限制。

第三方在运行中修改附魔效果或嵌套限制列表时，候选界面可能短暂沿用旧结果，最长到该条目的 5 秒有效期结束；付款校验不使用缓存。若需要判断实际收益，可在多装备背包中反复切换详情与强化页，再正常读档，检查日志 `Enchantment compatibility cache cleared` 中的 `hits` / `scans`。目前仅有自动化合成负载验证，尚未测量游戏内帧率或卡顿时间。

## 强化页面与确认

在装备详情中点击“进入强化”，会打开独立的三卡页面。每张卡片显示后端计算的当前 / 强化后数值，以及材料的持有 / 需要数量。选择卡片后还要查看成功率、失败后果，勾选风险说明并点击“消耗材料并尝试强化”才会支付材料。取消、返回装备详情不会收费，也不会刷新原卡片。

普通装备失败分解；受保护的唯一 / 任务物品失败降一级，并按原规则比例回退强化加值（+0 不会变为负等级）。附魔替换会额外提示原附魔被整体覆盖。材料、卡片或装备数据变化时，旧确认自动失效。金币刷新仍在点击刷新按钮时即时扣除。

预览中的攻击 / 防御采用“基础值 + 本模组加值”，不是包含技能、药水的最终战斗数值；性能卡另列受引擎上限约束的锻造倍率。攻速按该武器基础速度计算，上限为基础值的两倍；耐久卡保留已有耐久缺口；充能容量受 65535 上限约束。查看预览不会修改装备。

游戏内验收：比较七类卡片的预览与成功后的数值；检查临近重量 / 攻速 / 耐磨 / 充能上限；取消确认后核对材料未扣除；分别测试普通物品失败分解和受保护物品降级；确认期间关闭面板、离开设施或死亡读档后，不应保留旧确认。

配置文件位于 `Data/SKSE/Plugins/DurabilityManager.rules.json`，重启游戏后生效。请在更新安装包前备份个人修改。文件缺失使用内置默认值；JSON 语法、版本或数值校验失败时，整份覆盖配置被拒绝并回退默认值，原因写入 SKSE 的 Durability Manager 日志。

## 可调整范围

- `ranges`：`performance / weight / speed / durability / wear / charge` 六类数值卡，各为四个 `[最小值, 最大值]`，顺序为微弱、标准、强效、极强。区间必须为正数、按强度排列且不重叠（端点可相接），单次原始值最多 10000。攻速、重量、耐磨和充能仍受到原生硬限制。性能、耐久和充能沿用现有强化等级倍率。
- `catalysts`：七类卡各自的催化材料列表，叠加到该装备的配方材料；至少一种。相同材料自动合并需求，武器和护甲不能作为催化材料，以保护装备实例。材料找不到会禁止选择受影响的卡片。
- `cost.growth`：前 50 级材料指数倍率，默认 1.16，允许 1.01 至 1.5。
- `cost.lateGold`：当前等级超过 +50 后的额外金币基数，默认 200，允许 1 至 100000。
- `cost.lateMaterials`：三个高阶材料，默认乌木锭、魔族之心、龙骨，在当前等级 +51、+75、+100 起加入需求。
- `enchantments.allow`：补充默认来源池之外的附魔。仍须通过类型、部位、有效效果和黑名单校验。
- `enchantments.deny`：排除某个附魔；排除基础附魔同时排除以它为祖先的变体。黑名单优先于白名单。
- `enchantments.denyPlugins`：按插件文件名排除，大小写不敏感。检查附魔及其祖先的初始来源和最终覆盖插件。
- `enchantments.ranking`：按附魔标识覆盖抽卡评分或固定挡位，详见下节。可省略，旧版 schemaVersion 1 配置继续有效。

材料和附魔标识支持 EditorID，也支持 `Plugin.esp|十六进制本地FormID`，例如 `Example.esp|012345`。后者按插件解析加载顺序，支持 ESL；不要填控制台显示的带加载顺序前缀的完整 FormID。示例插件名与 ID 仅示范格式，需替换为实际记录。日志会列出无法解析的附魔规则。

配置属于现有七类卡的规则接口；它不能添加第八类执行逻辑，也不会生成任意倍率的新附魔模板。效果强度使用来源模组已有记录，卡片挡位是估算排序，不代表跨效果的精确战力。

## 功能型附魔分档

v0.1.31 自动评分会忽略隐藏辅助效果，并遵守效果的“无强度”“无持续时间”标志。使用引擎 SoulTrap 类型的捕魂效果按 `30 + 0.5 × min(捕魂时限秒数, 60)` 评分；若标记无持续时间，则评分为 30。这里的 30 和 60 是抽卡平衡参数，不改变游戏里的捕魂时限、伤害或灵魂石行为。多效果附魔仍作为一个整体，累计其可见效果评分。

未使用 SoulTrap 类型的第三方脚本捕魂效果无法凭中文名字可靠识别，需要按实际 ENCH 记录配置。例如将某条附魔固定到标准档：

```json
"ranking": {
  "Example.esp|012345": { "tier": "standard" },
  "Example.esp|012346": { "power": 45 },
  "Example.esp|012347": { "power": 60, "tier": "strong" }
}
```

把 `ranking` 放在 `enchantments` 对象内。示例 ID 是占位符，必须换成真实附魔记录：

- `power`：0～100000000 的有限数值，替换该附魔整体的自动评分，只影响候选排序。
- `tier`：`weak / standard / strong / extreme`，分别对应微弱、标准、强效、极强。固定后，该附魔只能出现在指定挡位的附魔卡中。
- 可以只填其中一个；空条目、拼错字段或非法数值会触发整份规则回退默认值。
- 优先使用该附魔自己的配置；没有时沿基础附魔链查找，最近一条配置整体生效，不逐字段叠加。可用一条基础附魔规则覆盖整个系列，具体变体另行覆盖。
- 固定挡位不绕过黑名单、装备部位或有效性检查，也不会把原本不在卡池的记录自动加入。需要时另配 `allow`。
- 同一挡位内按评分接近程度加权随机，高等级偏向高评分；固定挡位效果保留最低抽取权重，避免“评分低但指定极强”的功能型效果永远抽不到。评分不是硬性分段，仍允许少量跨评分区间随机。
- 如果抽到的挡位没有兼容候选，会按原有 42/33/18/7 权重从有候选的挡位重选；材料、成功率和充能均按最终挡位计算。

日志会记录成功解析的分档规则、实际选中附魔的评分和最终挡位。重复标识解析到同一个 FormID 时保留第一条并记录警告；请只保留一种标识写法。

## 高等级成本

设当前强化等级为 L，卡片档位材料倍率为 T（0.75 / 1 / 1.5 / 2.25）：

```text
L <= 50：材料倍率 = T × growth^L
L > 50 ：材料倍率 = T × growth^50 × (1 + (L - 50) / 25)^2
额外金币 = 向上取整(T × lateGold × (L - 50)^2)，仅 L > 50
高阶材料 = 向上取整(T × (1 + (L - 解锁等级) / 10))
```

配方材料乘倍率后向上取整；每种催化材料数量为倍率向上取整。超过引擎有符号 32 位数量范围（2147483647）会禁止选择卡片。等级没有人为设置的玩法封顶，但计算机和游戏引擎的数值范围仍然有限。

## 附魔池与限制

默认从可用、非受保护的武器/护甲模板实际引用的附魔中收集候选。原版和 Summermyst 使用同一套规则；不是导入 Summermyst 所有魔法效果。特殊脚本、未标记唯一物品仍可能需要逐项排除。

武器接触附魔、法杖附魔、护甲恒定附魔分别过滤；基础附魔链中的穿戴限制全部检查。空记录、删除/忽略记录、无效数值、全部隐藏的效果和循环基础链被拒绝。多效果附魔作为完整单个附魔替换，不和旧附魔叠加。

每次抽到附魔卡时，日志会记录该装备可用替代附魔数量；启动日志列出各插件的来源候选数量（尚未按目标装备过滤），便于确认 Summermyst 是否提供了候选。卡片显示来源插件和各项可见效果的原始数值；脚本条件和最终实战效果以游戏为准。

## 游戏内验收（本地构建无法替代这些测试）

1. 在独立测试存档中准备两把相同武器，给其中一把建立独立实例；卸下它，在工坊选择附魔卡。确认另一把、其他容器中的同款装备不改变。
2. 对已附魔武器替换，重新装备并命中目标，确认旧效果消失、新效果生效，充能会消耗；已有充能强化只应用一次。
3. 对护甲、服装、戒指及盾牌替换，重新穿戴后检查主动效果；换下再穿上，确认效果不重复。对穿戴中的装备点击卡片应被阻止且材料不变。
4. 确认卡片出现适用的 Summermyst 效果并实际触发；对不适合通用替换的效果加入 deny，重启确认不再入池。
5. 用唯一/任务物品测试，不能抽到或应用替换卡。普通强化失败仍只分解选中实例；保护物品数值强化失败仍降级。
6. 替换后保存、重启读档，以及死亡重新读档；确认附魔、充能、强化等级、耐久与面板均正确。
7. 对 +50 / +51 / +75 / +100 装备检查卡片需求及实际扣除数量；材料不足时不能支付。
8. 将攻速强化至 2×、重量降至 0.1、耐磨强化至配置上限，再产生新卡组；对应已满类型不应出现。如果剩余类型少于三种，允许重复抽取仍有收益的类型。
9. 为装备 A 刷新两次，记录三张卡片及下次 240 金币费用；切到 B 再回到 A、反复使用锻造设施、离开工坊范围再回来，都应恢复同样的卡片及费用。A 完成一次强化后开启新轮次；B 的卡片不改变。
10. 对已损坏装备先查看卡片再修复，同一张卡应解除“请先修复”限制；附魔卡卸下后解除穿戴限制，不应要求付费重抽。读档/新游戏会清空会话卡组，这是当前明确的边界。
11. 用实际附魔 ID 配置固定挡位，重启后检查卡片和日志；确认它只出现在指定挡位。用基础附魔规则覆盖系列，再给具体变体单独覆盖，确认最近规则优先。捕魂预览应显示“捕魂时限”，装备实际效果保持来源模组的规则。

目前自动测试覆盖功能型效果评分、固定挡位匹配与空挡位重选、分档配置校验、默认配置一致性、0～10000 级成本单调增长、浮点/整数溢出边界、强化上限判断，以及不同实例卡组/费用隔离、轮次更换和会话清理。真实记录解析、附魔应用、第三方脚本、游戏存读档与死亡流程仍需上述实机验收。
