# 四把法杖的专属法术 · 玩法设计 v0.1

> 实现进展：四把模型与四种法术原型见 [原型说明](staves-prototype.md)。本文保留原设计目标，实机验收尚未完成。

状态：用户同意尝试四种机制；本文是第一版可实施设计，数值为原型起点，尚未制作法术、脚本或游戏测试包。外观采用已认可的 `art/concepts/geometric-staves-redesign-01/concept.png`。旧组已删除，不恢复旧模型。

## 共同体验

- 每把固定一种专属施法能力，通过对应法杖使用；不发放可空手施放的法术书。
- 使用原有左右手施法键。第一版全部采用短蓄力、一次释放，不增加副技能键、模式切换或独立界面。
- 消耗法杖充能，使用已有充能流程。暂不同时扣玩家魔法值，也不加入独立资源条。
- 预定先验证单手玩家体验；事件和状态从开始就记录实际施法者、法杖类型、施法实例与手别，后续双持 / NPC 验证通过后再宣称支持。
- 固定法杖能力需武器与附魔 / 魔法效果记录配套。专属机制必须校验来源，辅助效果不得作为可学习法术暴露。
- 以下伤害均是抵抗、难度、天赋前的设计基准，不是保证的实战伤害。充能按 1000 点容量举例，不改变现有武器强度。

| 法杖 / 能力 | 玩家掌握的技巧 | 蓄力目标 | 每发基础伤害 | 每发充能目标 |
| --- | --- | --- | --- | --- |
| 余烬·叠炬 / 三烬迸发 | 连续命中同一目标 | 0.45 秒 | 30；第三击额外爆发 90 | 20 |
| 流萤·回梭 / 往复光梭 | 穿透角度、回程走位 | 0.55 秒 | 去程 45、回程 45 | 30 |
| 寒汐·悬阶 / 四阶寒律 | 控制走廊和接近路线 | 0.65 秒 | 四段各 15 | 30 |
| 梦隙·折界 / 裂隙回响 | 预判敌人 1.2 秒后的位置 | 0.70 秒 | 命中 15、延爆 105 | 40 |

充能费用是初始配置目标；引擎费用与当前角色修正对齐后实测。每次成功释放只支付一次，取消蓄力不支付，后续爆发 / 回程 / 波次不重复付费。双持与快速切换不能绕过实例上限；若施法拦截不能可靠做到“拒绝释放也不扣费”，应先解决机制再开放连续施放。

## 1. 余烬·叠炬：三烬迸发

**操作循环：命中一次 → 再命中 → 第三次击中引爆 → 重新叠印。**

### 效果

1. 发射短拖尾的红色棱片弹，命中角色造成 30 火焰伤害。
2. 对该目标增加一层烬印；第二次命中刷新剩余时间。标记 4 秒内未再次命中则全部消失。
3. 第三次有效命中先造成本次 30 伤害，再消耗三层，在目标当时的位置产生半径约 2 米、90 火焰伤害的单次爆发。爆发可伤及附近合格敌人。
4. 三发全中对主目标共 180 基础伤害，耗能 60；分散攻击会延后引爆。打空、打墙、被完全抵挡不增加烬印。

烬印按“施法者＋目标”独立记录，同一人两手红杖共享层数，其他施法者不代为引爆。爆发不能给任何目标叠印，避免连锁递归。目标死亡 / 卸载时清理；如果第三击基础伤害致死，已经成立的第三击仍在已捕获位置爆发一次。完全火免目标不以零伤害命中刷出爆发。

### 看见与听见

- 待机：低强度轮廓光。
- 蓄力：杖头叠片由下往上短暂亮起；不移动实体片。
- 一 / 二层：目标附近显示一 / 两枚小红色棱印，用目标标记表达层数。杖头只给短促命中反馈，不把某一敌人的层数显示成全局状态。
- 第三层：棱印向内聚合，爆成短促几何碎片；层数声效逐次升高，爆发后归于安静。

## 2. 流萤·回梭：往复光梭

**操作循环：对准一列敌人发射 → 转向前调整站位 → 让回程再穿过目标。**

### 效果

1. 发出一枚薄荷绿色扁梭，直线前行最多约 18 米；角色不截停它，实心墙体会触发提前返回。
2. 在到达最大射程或碰墙的转向瞬间，记录施法者此时的位置作为返回终点，走一条新的直线路径。转向后不再自动追踪，不能无限绕场。
3. 去、回程对每个目标各最多命中一次，各 45 非元素魔法伤害。多次触碰同一角色也不能反复结算。
4. 回程碰到新墙面则消散；到达终点或总寿命超过 3 秒亦清理。每名施法者最多一枚在途光梭，两手共享上限。

这让转向前的侧移有实际价值，转向后的走位不能继续弯折轨迹。返回的伤害不是锁定原目标的自动补伤；目标离开路径就会躲开。去程与回程分别保留命中集合。

### 看见与听见

- 蓄力：细光沿双带向梭形空腔流动。
- 发射：短而清楚的梭形实体光片，尾迹保持很短。
- 回程：光梭亮度轻微提高，出现方向清楚的双线短尾；短促转向声提示侧移窗口结束。
- 命中：小型交叉光纹，不产生爆炸雾。

**实现风险最高。** 需要真实的穿透判定、墙面阻挡和独立返回路径。普通飞弹变色或在原目标上补一次伤害都不满足此玩法；若引擎投射物路径不合适，应验证专用移动对象＋连续扫掠碰撞方案，不能用低频位置采样代替连续碰撞后宣称不会漏判。

## 3. 寒汐·悬阶：四阶寒律

**操作循环：朝敌人将经过的地面释放 → 寒律由近及远展开 → 用最后一阶截住前进。**

### 效果

1. 释放时固定方向；从施法者前方约 2 米开始，在约 2 / 5 / 8 / 11 米处每隔 0.22 秒依次激活一段寒能横带。
2. 每带宽约 3 米、纵深约 2 米，每次只结算一次，造成 15 冰霜伤害和 25% 减速，减速持续 2 秒。重复命中刷新持续时间，不叠加减速比例。
3. 第四阶若命中仍持有本次前三阶减速标记的目标，追加 0.7 秒短定身；只在第四阶受击则正常伤害与减速。
4. 同一目标的此类定身结束后 6 秒内不能再次触发，多个施法者也不能交替无限锁住。对定身免疫或不适用的目标保留允许生效的伤害 / 减速，不承诺强控巨型敌人。

不创建可站立冰墙，不改变导航网格。各段需落地投射、检查障碍和高度差；遇实心墙或断崖时停止后续段，不隔墙从另一侧继续展开。竖直瞄准或没有有效地面的施放如何拒绝且不扣费，需要在输入原型里验证。

### 看见与听见

- 蓄力：杖头阶梯按顺序亮起。
- 展开：地面四条低矮的青蓝几何光带按节奏短暂出现，最后一段稍亮；不用大面积冰雾。
- 定身：脚部出现简短方形束环，不把角色包在大型实心冰块里。

## 4. 梦隙·折界：裂隙回响

**操作循环：击中并留下位置标记 → 判断敌人是否会留在附近 → 延迟爆发。**

### 效果

1. 紫色折面弹命中角色，造成 15 非元素魔法伤害；命中墙面 / 地面也可以留下一个裂隙。
2. 裂隙固定在命中瞬间的世界坐标，不跟随被击中的角色移动。
3. 1.2 秒后，在半径约 2.5 米内造成一次 105 非元素魔法伤害。爆发前从裂隙检查目标遮挡，不能透过实心墙结算。
4. 每名施法者最多同时存在两个裂隙；每次爆发只对每个目标结算一次。目标离开范围即可躲开主伤害。

单次全部命中为 120 基础伤害。裂隙不会因原目标死亡而取消；它只依赖有效的固定位置与施法者归属。没有碰到实体的弹体正常过期，不在任意空中位置生成裂隙。

### 看见与听见

- 蓄力：杖头内部折面依次亮起，保留实体结构不变形。
- 留痕：紫色小折框清楚标出爆发位置与大致范围；对地面法阵做表面法线贴合，墙面命中采用局部立体标记。
- 最后 0.3 秒：折框向内收缩、音调提高，给敌人和玩家明确的时间反馈。
- 爆发：短促展开的三角光片，结束后立即消退。

## 配合与边界

- 蓝杖先减速，紫杖再布置延爆；低速目标更容易留在范围内，但不会保证命中。
- 蓝杖限制接近路线，绿杖沿纵向去回穿透；绿杖操作收益来自路径，不额外增加自动追踪。
- 红杖奖励集中攻击，紫杖奖励时机，避免两把都变成无条件大范围火球。
- 四把所有辅助伤害统一按实际施法者归属；第一版设计目标为不误伤玩家及其当前队友。敌对 NPC 持有时不能把玩家永久排除在合法目标之外。
- 目标抵抗、免疫和难度通过正常魔法伤害链处理，不用直接改 Health 绕过。最终魔法学派、关键词和天赋缩放须配合引擎原型校准；暂不宣称兼容所有战斗大修。
- 已发出的弹体可完成短寿命流程，切换武器不能复制或重置在途名额。施法者死亡、跨场景、读档时取消遗留实例并清理临时对象，不能读档重复引爆。
- 标记上限建议每名施法者 16 个目标；达到上限先回收已过期目标，再清理最早的非满层标记。临时裂隙、扫掠状态不能无限堆积。
- 暂停菜单冻结玩法计时；仅在游戏继续运行时推进。所有计时单位在实现中统一，不能混用真实时钟和暂停中的游戏计时。

## 对模型的直接要求

先落实法术所需的附着点，避免做完模型再挖改结构。

| 法杖 | 模型需预留 | 原型阶段不依赖的动画 |
| --- | --- | --- |
| 叠炬 | 每片独立命名；上端发射标记；可分别点亮的材质或遮罩 | 冠片展开 / 飞离 |
| 回梭 | 梭腔中心发射标记；双带路径可用作流光定位 | 整根杖头旋转 |
| 悬阶 | 各层可定位；杖头统一发射标记 | 每层机械伸缩 |
| 折界 | 折面内腔中心标记；独立内侧发光面 | 折面开合 |

第一、第三人称均需验证发射位置。不能直接承诺引擎会使用任意新增节点，须实测武器发射点 / 特效挂点流程。先做单个可靠发射点，逐片点亮属于后续可选表现，不阻塞核心玩法。

## 技术调查结论（未实现）

本仓库 `mods/magic-arrows` 的 README 与执行层已记录命中位置、真实射手归属、临时施法点和读档清理方向，可作为实现参考；它的箭矢命中接入不等于法杖飞弹接入，不能直接搬过去便视为已验证。

Creation Kit 的魔法效果文档指出，同一法术 / 附魔中的效果需要匹配施放类型，多效果时并非每个效果都显示自己的投射物。因此本设计采用统一的一次释放入口，再由有明确实例身份的辅助效果编排后续步骤；四段波次不能靠堆四个主飞弹效果保证实现。

资料：[Creation Kit — Magic Effect](https://ck.uesp.net/w/index.php?section=16&title=Magic_Effect)。参考说明只用于约束设计，不代表本机已测通。

初步实现候选：红杖的目标状态与紫杖的定时位置效果可先评估 Papyrus / 原生效果组合；绿杖连续碰撞、蓝杖地形检测和精确实例状态可能需要 SKSE 原生层。是否新增 DLL 依技术实验决定，本轮不安装依赖或改主插件。

## 原型顺序与通过标准

1. **公共入口 + 红杖**：用临时简单模型验证一次释放只扣一次充能。连续三发命中恰好爆发一次；4 秒过期、被挡、不命中、两名施法者和基础伤害致死均正确。
2. **紫杖**：固定位置延迟爆发。敌人离开旧位置可躲开；墙体挡住伤害；原目标死亡不迁移裂隙；暂停 / 读档 / 切换场景不残留伤害。
3. **蓝杖**：平地、台阶、坡道、门口、墙后和断崖分别验证。四段不越过实心障碍，减速不叠乘，强控不会无限接续。
4. **绿杖技术样机**：先测单枚去回、碰墙、移动施法者和两次命中上限，再测试穿过多个高速移动目标；路径失败时不以自动补伤替代。
5. **外观整合**：四套模型按概念图还原，接入上述发射与反馈；随后分别验收双持、随从 / NPC、伤害与充能平衡。

只有完成对应游戏测试才称为可玩法杖。原型之前不预留未经核对的 FormID，不修改既有记录身份；正式新增武器时执行本模组的物品箱、SPID、打包和安装要求。
