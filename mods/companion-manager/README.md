# 同行 · Companion Manager

独立重写的随从管理模组，使用 SKSE、Meridian UI 和自有任务 / AI 包。未使用 Horde 源码或素材。

## 1.4.1 · 对话招募自动纳入 · 64 位同伴

三个入口：我的队伍 / 随从名册 / 全局设置。使用原版 NPC 对话招募，退出对话后等待数秒，同伴会自动纳入独立名册；确认自有槽位绑定成功后释放原版招募名额，即可继续对话招募下一位。后续等待、离队、居所与法术由面板管理。「我的队伍 → 招募同伴」仍作为直接招募和手动纳入其他队友的补充入口，支持搜索、刷新和不可招募原因。名册中的同伴可重新招募。队伍采用卡片网格，点击卡片进入详情，只保留概览 / 行为 / 魔法三个标签页；返回按钮回到网格。半透明深色面板、浅青色强调，可调整字号与不透明度。

本版已接入真实管理指令。原生 DLL、Papyrus 和网页编译、结构与规则测试通过；**Skyrim 内的 AI、模型渲染及跨存档行为仍需集中实测**，不能将编译或浏览器模拟等同于游戏验证。

- **Shift + F** 打开 / 关闭，Esc 关闭。输入文字时 Shift + F 不关闭面板。其他 Meridian 页面占用焦点时不抢占。
- 全局字号默认 16px，可调整为 14–18px；已有存档保留保存的字号。
- **面板打开时游戏继续运行**，鼠标与按键由 Meridian 捕获，保证招募与居所的 Papyrus 调用能够执行。关闭后恢复游戏输入。
- 独立管理 64 位同伴（在队与离队共用名册容量）：招募、离队、重新招募、释放名册。释放时恢复原始行为、死亡保护与等级上限，恢复被禁用法术；已通过书本学习的法术保留。
- 单人 / 全队跟随、等待、召回；自由活动；跟随距离三档；非战斗状态下跨区或落后约 100 米自动跟上。等待的同伴不会被自动召回。
- 将玩家当前位置设为个人居所，离队后前往居所；清除居所后恢复原有日程。
- 战斗：避免交战（降低攻击性和信心、尝试停止战斗）、Essential 死亡保护、当前抗性。避免交战不等同于免疫伤害。
- 法术：列出已知普通法术与学派、消耗玩家持有的法术书教学、禁用 / 恢复法术；成功学习并确认扣除一本书后才报告成功。任务书与重复教学会拒绝。
- 概览：等级、三围、基础属性、十八项技能与抗性。装备页和套装入口已从新界面移除。
- 成长：真实等级、九项战斗技能、成长上限；符合条件的随玩家成长人物可将上限提高至至少 300，关闭恢复原值。固定等级 / 原本无上限人物不覆盖。
- 人物预览已移除，不再请求 NIF 或创建渲染层。魔法页将已知法术和背包法术书分别以网格展示，并提供效果介绍、正文、学派与持有数量。
- 设置与名册使用独立 SKSE co-save 记录保存，读档时重映射 FormID。预加载清空界面，存档会话标识拦截旧页面指令，重复请求不会重复扣书 / 转移。

## 接管范围与边界

仅管理非儿童、非敌对、非交战中的独立 NPC，剧情场景进行中暂不接管。自动衔接仅针对 Skyrim.esm 的 DialogueFollower 人类随从槽位，不扫描接管动物或独立剧情框架。对话界面关闭且状态稳定后，先验证自有别名绑定，再清理该 NPC 的原版随从别名、等待计时和计数；不调用原版解散函数，不覆盖原版脚本文件，不清理其他剧情任务别名。接管前的等待状态保留；名册满员、绑定失败或原版槽位目标发生变化时不强制释放名额。已有队友也可在详情顶部点击「纳入同行管理」，无需先解散。其他随从框架仍在运行时可能覆盖行动安排；非队友且受任务 AI 包控制的人物仍不接管。

人物名册优先显示，另读取引擎当前可枚举队友及约 60 米内人物；最多 128 人，每人最多 512 个普通法术和 512 类背包物品，玩家背包最多 512 类。异地距离显示为未知。页面在打开、手动刷新与指令完成后刷新。

任务物品不允许调整或转移；已装备物品须先卸下。单件附魔 / 强化物品转移时保留 ExtraDataList；同类多个独立实例不能靠基础 FormID 区分，会要求先通过游戏交易拆分。套装保存基础物品标识，不能指定同类多个附魔实例、左右手组合。这里的装备类型是武器 / 护甲分类，不是精确护甲槽位。

个人居所、战斗、成长和法术设置在普通离队后保留；要彻底交还其他系统，用“释放名册”。卸载带任务与脚本的模组不作为本轮测试的一部分，测试前另存档。原版 / 自定义剧情 AI 的兼容性仍需逐人物验证。

## MO2 安装与测试

依赖：匹配游戏版本的 SKSE、Address Library、Meridian UI（本机 1.5.0）。本机目标 Skyrim SE 1.5.97，其他运行时未验证。

完整安装包含：

```text
CompanionManager.esp                 # ESL 标记，必须在 MO2 右侧启用
Scripts/CMController.pex
SKSE/Plugins/CompanionManager.dll
MeridianUI/companion-manager/index.html
MeridianUI/companion-manager/assets/...
```

本版新增 ESP 与脚本，不能只替换 DLL 或网页。安装脚本自动查找现有 CompanionManager.dll 所在目录（允许用户改过目录名），先备份到 MO2/companion-manager-backups，再覆盖完整包并验证 SHA-256。不修改正在运行的 MO2 配置；旧目录名含“只读测试”时仍保留，以维持原有勾选状态，但内容已更新为完整测试版。

1. 刷新 MO2，确认左侧同行与 Meridian 已启用，右侧 **CompanionManager.esp** 已勾选。通过 SKSE 进入单独的测试存档。
2. Shift + F / Esc 开关面板、输入框打字、Alt-Tab、打开其他管理 UI，确认焦点与快捷键。
3. 对已有队友先点击详情顶部「纳入同行管理」，收到成功回执后验证行为开关和法术教学。再对已登记同伴测试名册重招、单人 / 全队等待、跟随、集合；跨区域与落后时自动跟上；等待时留在原地。
4. 设置居所 → 离队 → 观察返家 → 名册重招；清除居所、释放名册，确认原有日程。
5. 教学一本书，核对已知法术和玩家书本数量；禁用、恢复；尝试任务书 / 已掌握法术。
6. 检查三页内容与卡片返回导航，确认没有人物预览、装备或额外标签页。
7. 死亡保护、避免交战、成长上限开关，核对原值恢复。
8. 保存 → 退出至主菜单 → 读档 → 重启游戏读档；交叉载入另一存档，确认人物、设置、居所与禁用法术独立。

日志在 SKSE 日志目录的 CompanionManager.log。收到“结果未确认”时先刷新检查双方状态，不要立即重复物品操作。

## 开发与验证

需要 VS2022 C++、xmake、Node（测试需要 TypeScript 类型擦除支持）、Python、Creation Kit Papyrus 编译器，以及工作区 reference/example-skse-plugin/lib/commonlibsse-ng。源脚本与插件生成器在 source，游戏运行时不需要 Python 或 Creation Kit。

```powershell
# 模组根目录：构建自有 ESP 和脚本
python source/build_plugin.py
python source/compile_scripts.py
python source/test_plugin.py
# native 目录
xmake f -m release -y
xmake build CompanionManager
xmake build input-rules-test
xmake run input-rules-test
xmake build state-rules-test
xmake run state-rules-test
# web 目录
npm ci
npm test
npm run build
# 模组根目录
pwsh -File packaging/package.ps1
pwsh -File packaging/install-local.ps1 -PackageDirectory '<刚生成的完整包目录>'
```

ESP 使用 Skyrim.esm 的标准包模板数据作为参数实例，没有复用其他随从模组的数据。记录布局参考 [xEdit TES5 definitions](https://github.com/TES5Edit/TES5Edit/blob/dev-4.1.5/Core/wbDefinitionsTES5.pas)。SDK 来源与 MIT 授权见 native/vendor/README.md。

浏览器开发 `npm run dev`，端口 5186。`/` 使用与游戏相同界面的内存设计演示；`/tests/runtime.html?runtime=game` 是完整游戏界面的模拟桥接测试，有醒目“非游戏”标记，不打进发布包。`?runtime=game` 单独访问用于验证无原生桥接时不会出现演示人物。

## 1.1.2 修复

- 修复既有队友显示在队伍中却无法招募、无法开启任何管理操作的流程死路。接管通过原生条件检查与自有别名绑定后生效；失败回执保留未管理状态。
- 详情仅保留概览 / 行为 / 魔法。角色详情顶栏展示当前居所，并提供设置及清除入口，三个页签均可操作。
- 外层面板与装备工坊一致，固定上下 4vh、左右 3vw，无最大宽度限制。
- 日志增加未登记队友的接管资格、指令和执行结果，便于真实游戏排错。

## 1.3.0 新档布局

- 在队与离队名册共用 64 个名额；快照最多显示 128 位人物。
- 人物别名统一为 0–63，居所别名统一为 64–127；人物槽 n 的居所直接对应 n + 64。移除扩容时为旧存档保留的分段映射与兼容测试。
- 本版使用新存档。SKSE 名册格式版本更新为 2，不迁移旧布局记录；正常保存、读档和 FormID 重映射保留。
- 更新必须同时安装 DLL、ESP、PEX 和网页。已有游戏存档中的旧任务别名不属于本版支持范围。

## 1.3.1 默认成长上限

- 纳入管理及重新入队成功后，随玩家成长且原本有上限的同伴默认开启至少 300 级成长上限。原本超过 300 或无上限的角色不被降低，固定等级 NPC 不改变成长方式。
- 现有在队名册首次载入时应用一次默认值；之后手动关闭的选择会随存档保存，普通读档不会再次强行开启。重新入队会重新应用入队默认值。
- 提高的是成长上限，当前等级仍由角色的等级倍率、玩家等级等原有规则决定。
