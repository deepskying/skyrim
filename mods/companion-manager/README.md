# 同行 · Companion Manager 1.9.9

## 1.9.9 · 修掉套装漏穿强化装备的最后一环

1.9.8 让身份重分配与缺失退化匹配都照顾了套装，漏穿却还在。原因是**保存侧和换装侧看的不是同一批实例行**：套装是照着穿戴页存的（穿戴页 = `Wardrobe()` 的行 **加上** 它没列出的穿戴实例），而 `ApplyNamedOutfit` 只在 `Wardrobe()` 的行里找 key。于是：

1. 套装点名的那件强化装备（正穿在身上）在这次查找里不存在 → 被记成"缺失"；
2. 整套替换会把"套装没点名"的穿戴件全部脱掉 → 这件强化装备**被脱下来**；
3. 它上一步已经被算作缺失，所以不会再被装回去 → 漏穿。

现在的做法：

- **候选行与保存侧一致**：`ApplyNamedOutfit` 先把穿戴实例补进候选行（含穿戴页列出的、被行数上限挡掉的那些），套装能存的 key 换装时就一定能解析。
- **退化匹配补位**：找不到 key 时，优先用**未穿戴**的同 base FormID + 同附魔签名实例；没有备件时改用**已穿戴**的同签名实例——这表示"这件本来就在身上"，于是它会被算作套装成员，不再被当成杂项脱下。
- 仍然无法解析的条目会写一条 `Outfit unresolved ...` 日志（含 base FormID、附魔 FormID、充能、同 base 行数），下次再有异常可直接从日志定位。

旧套装仍需重新保存一次才会带上附魔签名；任务装备、角色皮肤与武器／盾牌／弹药规则不变。

## 1.9.8 · 修掉强化过的装备在套装里漏穿

强化（或任何"临时卸下再装回"）会让引擎把背包堆的实例编号复制到穿戴件上，于是同一个编号同时描述两件装备。此前的身份重分配固定把编号留给背包堆、让穿戴件换新号，套装里存的 key 就指到了另一件上，换上套装时按设计跳过"缺失实例"，那件强化过的装备便留在外面。

- **套装引用优先**：重分配之前先收集所有角色（含玩家）已保存套装引用过的 key。这个 key 仍被套装引用时，**穿戴件保号、背包堆换新号**，套装指向的实例身份不变；没有任何套装引用它时维持原来的让位规则（背包堆保号，锁定与收藏不受影响），两者都引用或都不引用也回落到原规则。
- **缺失实例退化匹配**：key 找不到时，只在**同一 base FormID + 同一附魔签名（附魔 FormID 与充能）+ 未穿戴**的实例里挑一个，绝不误穿另一件附魔复制品；挑不到就仍然算缺失、按原样跳过。
- 保存套装时会一并记录附魔签名（没有附魔也记录为 0）。因此**历史上已经失效的旧套装需要重新保存一次才能恢复**——没有签名可依据的旧记录不会被猜测匹配。快照 `version` 3 → 4。

任务装备、角色皮肤与武器／盾牌／弹药的既有规则不变。

## 1.8.18 · 打开更快、顶栏不透明、换装立刻可见

- **打开更快**:打开面板时先切换页面、再送数据——前端本来就留着上一份快照,所以「随从装备」可以立刻画出来,不必等原生把整份快照重新算完;同时快照里**只有当前面板正在看的那位随从**才带库存与服饰负载(以前每位在队随从都要各走一遍库存遍历与服饰合并,那是快照里最贵的部分)。面板关闭时把这份"关注"交还,其它页面照旧拿到完整快照。
- **顶栏与滚动条不透明**:紧凑面板的表头改成纯色 `#0c0e11`,列表滚动条轨道也补上纯色底(滑块浅灰),两者都不会再透出背后的游戏画面。
- **换装立刻可见**:装备或卸下之后显式刷新该同伴的 3D 模型(`Actor::Update3DModel`)。这正是"暂停面板后面站着的那位随从当场换上新装备"的关键——和 SkyUI 里换装备能看到角色变化是同一个道理;此前引擎在暂停状态下不一定会重建可见模型。

按实测反馈调整「随从装备」页的版式:

## 1.8.14 · 装备预览取景与列表间距

「随从装备」页的一组体验修正:

- **列表改成一行一卡**:行与行之间留 2px 间距,每行自带半透明底(与面板其它卡片一致),表头保持吸顶。此前 39 行挤在同一块底纹里,扫读时容易串行。
- **已收藏的行给淡蓝底**:收藏物在列表里一眼可辨(悬停与选中时蓝色加深一档,不会与高亮态撞色)。
- **名称前带类型图标**:按部位与材质显示图标——盾牌、头盔、手套、项链、戒指、护甲、服装各一个,重甲与轻甲同形不同色(暖色/冷色);图形取自 `shared/iconfont`,与物品清单面板同源,详情标题也带同一枚图标。
- **左侧列表占满剩余高度**:列表不再固定在 56vh,而是拉伸到与右栏同高再内部滚动,面板下半部分不再留白。
- **移除「手动调整」页签**:面板只保留「整套随机」与「随从装备」。部位网格页与装备卡片一并删除;若还有旧入口按「part」请求(例如旧版原生端),会落到「随从装备」页——穿脱、配对与槽位替换本来就是这一页的职责。
- **预览区加大**:3D 视口高度由 230px 提到 340px(窄屏 240px)。
- **取景修正(平台侧)**:模型在视口里显得过小**不是容器尺寸问题**,而是 Meridian 的取景把包围球半径下限钳在 1 单位——戒指、项链,以及按"米"级导出的装备掉落模型都被当成半径 1 取景,于是缩在正中间(实测约占高度 16%,正常取景应约 80%)。已在 `mods/meridian-ui` 的本地补丁里修掉(半径只保留 0.05 的防退化下限),半径大于 1 的模型行为不变。**本版本需要搭配这份打过补丁的 Meridian**——补丁与二进制归档在 `MO2\companion-manager-backups\meridian-nif-fix-1.5.0\`,平台源码与 `patches/` 在仓库 `mods/meridian-ui`。

## 1.8.13 · 新增「随从装备」页与装备模型预览

穿搭面板新增第三个页签「随从装备」。左侧是一条平铺的服饰列表——不按部位分网格、不做分类切换，把随从库存里全部服饰一次列出（武器、箭矢、药水、材料、书、杂物、金币宝石都不进这个列表）。每行写明名称、数量、重量、价值，已穿戴的行加亮色标记并标注「已穿戴」；列表上限 512 行，因此保留搜索框，可按名称即时筛选。

右侧上半是 3D 模型预览，下半是属性区，属性显示**与当前穿戴的对比**：护甲一栏给出这次操作之后的护甲总值与增减（例如 `41 (−3)`、`56 (+20)`），另外列出当前护甲、部位、类型（轻甲 / 重甲 / 首饰 / 服装 / 其他，按 `ArmorLight`、`ArmorHeavy`、`ArmorJewelry`、`ArmorClothing` 关键字判定）、附魔、数量、重量、价值，以及这次操作将要换下的同槽位服饰。对比算的是"点下去之后你会得到什么"——已穿戴的服饰预览的是卸下后的结果。护甲值按整数显示：记录里的护甲值是浮点（含附魔与天赋的小数贡献），面板只显示整点，并且增减由取整后的两个总数相减得到，所以「当前护甲 + 增减 = 操作后护甲」永远成立。

交互是"悬停即预览、点击即切换"：鼠标悬停只更新右侧预览，不发任何命令；点击、或选中后按 Enter 才真正穿脱；方向键上下移动选择并预览，用键盘后预览交还给选中行。穿上时按槽位替换（多槽位服饰会一并换下同部位装备），任务装备不能被卸下，目标部位被任务装备占用时这次替换会被拒绝并提示。对话第三条「调整穿搭」现在直接打开这一页；「整套随机」与「手动调整」两个页签行为不变。

模型预览用 Meridian UI 的 NifView + RenderLayer：面板里预留一块空的视口，原生按它的屏幕矩形铺一层渲染面，模型取护甲的 `worldModels[sex]`（性别按该随从的 actor base 判定，取不到时回退另一性别），拖拽旋转、滚轮缩放、「重置视角」回到默认机位。三种情况各有各的说明：物品没有世界模型显示「此物品暂不支持模型预览」，NifView 扩展不可用显示「模型预览未连接」，加载失败显示「模型加载失败」。离开这一页、切换到别的页签或关闭面板都会清掉模型并隐藏渲染面，不会留下浮在其它界面上的图层。

原生快照为护甲记录补上 `mask`（部位掩码）、`armorRating`、`armorType` 与 `enchantment`，快照版本 2 → 3，前端类型、校验与修复同步。新命令 `toggleWear {itemKey}` 复用既有的延迟确认：脱下核对"该件确实不在身上"，换上核对"该件确实穿上、被替换的确实换下"。预览只走新的 `previewSelect` / `previewLayout` / `previewCamera` / `previewStatus` / `previewClear` 五个 UI 动作，快照结构没有变化。

## 1.8.12 · 穿搭对话升级为三条一级选项

同伴对话里不再有一个「穿搭调整」再展开子菜单，而是三条直接可选的对话：

1. **随机套装** —— 只从已保存的套装里随机挑一套换上，不再混入"从收藏重新组合"；一套都没保存时提示「还没有保存的套装：请先在伙伴穿搭面板保存一套」，不做任何改动。
2. **保存当前套装** —— 打开命名框，把当前穿戴保存为新套装（行为不变）。
3. **调整穿搭** —— 打开伙伴穿搭面板的「调整部位」页（当前行为；装备模型预览等后续版本再做）。

实现上把原来"一个父话题 + 三个 TCLT 链接子话题"改成三条各自独立的顶级分支（每条自带分支、话题与 INFO，条件沿用：已纳入管理的在队同伴），新增 `CMDialogue.RandomSavedOutfit` 原生函数，删除不再使用的 `RandomOutfit`。面板里的「随机一套」与定时自动换装仍按全局设置的概率在"已保存套装/从收藏重新组合"之间选择，只有对话的「随机套装」固定走已保存套装。

## 1.8.11 · 点击套装卡片直接换整套

「整套随机」页里点击已保存套装的卡片即直接换上整套，不再需要先选中、再点下方的按钮。卡片第三行写明"点击换上"；点击后卡片保持选中，下方列表显示该套装的每件服饰以及穿戴/缺失状态，可继续核对结果。原来的「使用此套装」按钮已移除，工具条只留「随机一套」（重新组合）与「移除当前套装」；「当前套装」卡片仍是只读预览，不会触发换装。战斗中、换装确认中或同伴不可用时，点击只切换预览并在提示里说明当前无法换装。

## 1.8.10 · 使用套装改为整套替换

以前使用已保存套装是"叠加":套装只补上它包含的服饰,当前穿着的其他部位原样保留,结果可能是套装 + 旧装备的混合状态。现在**玩家主动使用套装时改为整套替换**:先换下当前所有非任务、非角色皮肤的服饰(含套装没有覆盖的槽位、以及槽位里那件"套装实例已缺失"的替代品),再穿上套装内容;套装配不到的槽位保持空着,任务装备与角色皮肤始终保留,武器 / 盾牌 / 弹药不受影响。

换下与穿上在同一次延迟确认里核对(日志 `Outfit strip` / `Outfit dispatch` / `Outfit final ... removed=N`),遗留的禁止移除标记会先清掉。**自动定时换装仍不脱旧装备**,只补充套装配得到的部位——避免存档里某件套装部件已经不存在时,把无人看管的同伴脱空。面板「使用此套装」的说明文字同步更新。

需要整包安装(ESP 未变,DLL 与前端有改动)。改不动的边界:套装的实例全部缺失时(选不出任何部件)不执行任何操作,只提示缺失。

## 1.8.9 · 穿搭卡片透出角色

穿搭面板里的装备卡片原来是纯不透明底色,挡住身后的随从,换好衣服看不到效果。现在「整套随机」的物品卡片与「手动调整」的装备卡片改为半透明底色(默认约 56% 不透明),透明度跟随全局设置里的「面板不透明度」:滑块越高卡片越实,但始终不会变成纯色,最低也保留可读的文字对比。已穿戴高亮卡片(亮色边框/选中态)比普通卡片稍实一点,便于区分。新增 `cardAlpha` 规则与网页测试,锁定卡片永远带透明度。

## 1.8.8 · 撤回部位对话菜单与固定面板目标

实测后撤回 1.8.7 的 13 个部位随机对话选项：「穿搭调整」下级恢复为**保存当前套装 / 手动调整 / 整套随机**三项，ESP 里的部位记录、槽位全局变量与 `CMOutfitSlotTopic` 脚本一并移除（部位换装仍可在「手动调整」面板里做，含随机更换此部位）。整套随机只从收藏挑选的规则保留。

修复面板会自动换人：原生快照按**实时距离**排序，衣橱、法术与伙伴库存面板在未显式选人时取列表第一项，于是同伴走开或被其他人靠近时，面板目标会跟着变。现在选择被固定（`web/src/companion-selection.ts`）：已经选中的同伴只要还在名册里就保持不变，快照为空时也保留当前选择；只有该同伴离开名册才重新落到第一位。伙伴选择列表改为按姓名稳定排序，避免刷新时列表自身跳动导致点错人。

安装包回到五个 PEX 脚本；仍需整包安装（ESP、DLL、前端、脚本）。

## 1.8.7 · 对话换装菜单与收藏随机

「穿搭调整」的下级菜单重排为**保存当前套装 → 手动调整 → 整套随机**。原「指定部位」更名为「手动调整」（面板页签名同步），仍打开原来的部位面板，可手动挑具体那件、随机更换该部位或卸下，面板内的部位随机按钮保留。

随机整套的 30% 重新组合收紧为**只从收藏挑选**：随机换装不再穿上未收藏的备用装备，除非玩家在面板里点具体卡片（那仍是一次明确的手动选择）。手动整套随机依然可以替换当前穿戴（包括未收藏的当前装备），所以不会出现「收藏里挑不出替代品就卡住」的情况；自动定时换装维持只选收藏。无候选时的提示改为指出收藏。

本版曾把 13 个有名字的部位（头部、头发、身体、手部、前臂、项链、戒指、脚部、小腿、尾部、长发、头环、耳部）作为对话选项平铺，1.8.8 按实测体验撤回，部位换装仍只在面板里做。

## 1.8.6 · 战斗状态与队友停战

随从的"交战状态"改为按真实战斗判定：只有存在存活、已加载且敌对的战斗目标时才算交战。目标死亡、卸载、离开区域，或目标其实就是玩家/其他同伴时，残留的交战标志会在数秒宽限期后由守卫清除，面板与换装、取物、对话换装、自动跟随会随即可用，不再被引擎残留状态锁死（此前只有开启「避免交战」的同伴才会被清理）。

新增队友停战守卫：某位同伴的战斗目标是玩家或其他同伴时，立即对双方停战并写入日志（含目标 FormID、阵营反应、攻击性）。入队与读档后还会把同时在队的同伴两两提升为"盟友"关系等级（只升不降，最多每 15 秒提交 4 对），从源头消除吸血鬼同伴与黎明守卫向随从这类阵营对立引起的互殴；日志出现 `Companion allies set` 与 `Combat guard ...` 可用于复核。

## 1.8.5 · 实例编号冲突修复

装备背包里的一叠装备时，引擎会把这一叠的实例编号复制给穿戴中的那一件，于是同一位伙伴的库存里出现两条共用同一个实例键的记录。前端原本因此丢弃整份快照，表现为随从列表空白、状态栏提示"游戏数据格式不匹配"。本版在读取衣柜时检测重复实例键：保留背包那一叠原有的编号，给穿戴副本分配新的可用编号并记录日志；编号空间耗尽时只跳过该条并给出警告。前端同时改为逐条修复——重复键折叠、非有限数值与不一致标记修正、超长列表截断、无法使用的人物行单独跳过——并在状态栏写明原因，不再因为单条数据异常清空整个面板。

## 1.8.4 · 套装移除与法术直传

伙伴穿搭中选中已保存套装后，可移除该套装记录，当前穿戴和收藏保持不变。传授随从法术时点击按钮即提交，成功后仍校验并消耗一本法术书。

## 1.8.3 · 部位装备统一网格

指定部位下方将当前穿戴与可替换服饰合并到同一个大卡片网格，当前穿戴排在前面并使用亮色边框及「已穿戴」标记；卡片内提供卸下按钮。未穿戴卡片仍可直接点击穿戴，多槽位影响与隐藏穿戴标记保留。

## 1.8.2 · 套装命名归属与槽位高亮

对话保存请求绑定目标随从和当前会话，等待该随从的数据就绪后仅打开一次命名框。切换伙伴清除保存入口，取消、保存及返回面板不重复弹出；不再回退到另一名随从进行命名。指定部位使用亮色边框及「已穿戴」文字标明当前穿戴槽位，多槽位服饰同时标亮所有占用部位，卸下后随快照更新。

## 1.8.1 · 独立穿搭面板与卸装

「伙伴穿搭」独立为左侧顶级导航，对话中的指定部位与保存套装直接打开此面板。指定部位支持卸下当前具体装备，包括普通库存未显示但存在真实穿戴实例的装备；多槽位服饰提示全部影响部位，任务装备与角色皮肤仍受保护。卸下后延迟核对实际穿戴状态。整套装备改为宽网格卡片，长名称自动换行。

## 1.8.0 · 独立衣橱与穿搭对话

伙伴库存新增「穿搭」页签，提供整套随机和指定部位。指定部位列出 30–61 号全部槽位（盾牌不参与），点击服饰直接穿戴，也可随机更换此部位；多槽位服饰标明影响范围，并继续保护任务物品与角色皮肤。

每名随从独立保存命名套装，保存当前穿戴的衣服、护甲和饰品并全部收藏，不含武器、盾牌及弹药。列表记录具体装备实例，同款不同附魔不互相替代。应用时缺失的实例跳过，不预先脱光；多槽位服饰仍会替换它占用的其他部位。（1.8.10 起玩家主动使用套装改为整套替换：先换下套装未包含的服饰，见上方 1.8.10 条目。）选中已保存套装后可移除该套装记录，不改变当前穿戴和收藏。每人最多 64 套，随 SKSE co-save 保存并在读档时重映射 FormID；旧存档默认没有命名套装，其他记录保留。

整套随机默认 70% 选择已保存套装、30% 重新组合，概率在全局设置修改；没有保存套装时始终重新组合。对话入口改为「穿搭调整」，下级为「整套随机 / 指定部位 / 保存当前套装」；后两项关闭对话后打开对应面板或命名框。必须使用包含新 ESP、DLL、前端和五个 PEX 脚本的完整安装包。

## 1.7.9 · 识别普通库存漏掉的穿戴实例

手动换装的旧锁清理改为扫描原始 InventoryChanges 中的实际穿戴实例，不再依赖数量为正、最多 512 条的面板衣柜列表。非任务、可玩且与备用服饰槽位冲突的已穿戴装备，即使显示数量异常，也可清除遗留禁止移除标记；隐藏任务物品、不可玩装备与角色皮肤仍保护对应槽位。不改物品数量、不生成装备、不将异常穿戴记录加入出售候选。

日志增加 Outfit raw worn，包含库存计数、增量、面板可见性和锁定状态；只有角色模型、没有实际穿戴实例的物品另行记录，不猜测实例或强制删除。该版本修复原始穿戴记录被过滤的路径，修颜衣服与旧随从靴子的实际状态仍需游戏内复核。

## 1.7.8 · 修复原版招募交接

交接时核对原版人类随从槽位、脚本属性及计数，并保留已管理人物的在队／离队状态。原版槽位为空但计数为 1 时，须有本模组已确认的角色绑定并跨 tick 观察稳定状态，才尝试清除残留计数；计数不是 0/1、另一人物占用槽位、对话或原版解散进行中时不清理。解散前释放本人物仍占用的原版名额；通过原版对话重新招募已离队人物后正常重新入队。新增 Recruitment state 日志，显示占用人物、计数与绑定校验对象；脚本端执行前复核，DLL 执行后复核。未更改动物随从名额。

## 1.7.7 · 修正禁止移除参数

修正装备调用的 forceEquip 参数：该参数实际表示 PreventRemoval，旧版本误设为 true，会阻挡后续同槽位替换。新穿搭不再添加该锁；手动随机换装时，仅对有新服饰替换的同槽位、已穿戴、非任务且可玩的库存护甲清除遗留 ExtraCannotWear 标记。自动穿搭不清除已有锁。日志新增 removalLocked 与 Outfit unlock。收藏与出售保护保持原样；未知来源的同类锁无法按来源区分，因此仅在用户手动要求替换的部位处理。

参数语义参考 [SPID 实现](https://github.com/powerof3/Spell-Perk-Item-Distributor/blob/master/SPID/src/Outfits/Helpers.h)。

## 1.7.6 · 延迟确认换装结果

穿戴请求发出后跨帧复查，最多等待 2 秒，不再在同一调用中直接判定失败。同一人物确认期间不重复派发；读档清空待确认记录。日志增加延迟穿戴结果、仍穿着的装备及角色模型装备 ID，用于区分实际穿戴失败与显示异常。修颜的实际失败原因仍需新日志验证。

## 1.7.5 · 修复手动换装选择与失败提示

手动随机换装优先选择未穿戴的合格服饰，再优先收藏，避免已收藏的当前衣服一直挡住未收藏备用衣服。定时自动穿搭仍只选择收藏服饰。区分无可用服饰、槽位或锁定限制、搭配未变化、穿戴未确认；部分成功单独提示。日志记录人物、服饰实例、槽位、保护与收藏状态，以及每件新服饰的穿戴确认结果。

## 1.7.4 · 玩家交付装备保护

玩家向已纳入管理的同伴转交武器、护甲或服装后，自动加入现有锁定列表，防止自动出售；锁定衣甲仍可作为自动／手动换装候选，支持在库存面板手动解锁。按交易事件的实例 ID 优先匹配；没有可唯一识别的实例 ID 时，保守锁定同伴库存中的同款装备。只处理新发生的交付，不追溯已有库存的来源。

自动出售始终排除全部炼金物品（食物、饮料、药水和毒药），与来源及是否手动锁定无关。交付锁定完成前暂缓该同伴出售，防止交易与自动出售时序冲突。游戏内交换、保存读档及换装仍待实测。

## 1.7.3 · 修复人物概览按钮换行

## 自动行为与衣柜

- **行为管理**：通用设置、拾取行为、售卖行为、自动穿搭、主动对话、活动记录。拾取 / 售卖 / 穿搭 / 提醒支持全队默认与个人覆盖；恢复沿用全队即可继续继承默认值。原通用行动开关仍逐人设置，提供全队跟随 / 等待。
- **战后拾取**：战斗停止后等待 4 秒，搜索窗口 3 分钟；走近并朝向目标，尝试原版拾取 / 搜尸动作，动作不可播放时以朝向停顿为最低表现。敌袭立即取消待执行转移，已完成的拾取保留。只搜本次记录的敌人尸体、无主地面物品；无主容器默认关闭。跳过玩家丢弃物品、犯罪操作、上锁和任务物品。范围 5–60 米、类别、最低价值与价值重量比可调；金币 / 宝石 / 灵魂石免价值门槛。转移前逐项核对负重，可只取放得下的部分。
- **到店售卖**：玩家在营业商家附近时，伙伴走近商家、双方看向对方，并显示文字交谈提示后交易。当前为脚本化文字交谈表现，不新增原版有声对话树。尊重商家类别、营业时间、条件、赃物收购与实际金币余额。出售所有符合条件的未收藏物品，收入进入伙伴背包；按伙伴口才计算价格，不套用玩家专属交易加成。完成通知列出件数与金币，活动记录保留本次会话最近 40 条。商家冷却 60 秒，多个伙伴依次交易。
- **伙伴库存**：点击任意库存物品卡片切换锁定，星标与边框同时提示；药剂、食物、材料、杂物和装备均可锁定。锁定物品永不自动出售，普通堆叠物品按整组保护。旧装备收藏记录继续作为锁定状态使用，锁定服饰仍可参与自动穿搭。按角色、名称与库存类别筛选。取物时点击卡片切换选择，右上角显示大尺寸选中标记；不可取走的物品不显示选择标记。支持多选和数量，显示总价值、总重量及玩家取走后的负重；超过容量拒绝整个选择。
- **自动穿搭**：默认每 12 游戏小时从收藏服饰中随机挑选槽位不冲突的装备，也可点「试换一套」。不随机更换武器，不强行脱下没有替代品的其他部位。换装后保持当前穿搭，交战不触发恢复；换下的装备按普通库存规则处理。
- **主动提醒**：负重余量不足 5、玩家余量大于 1 时请求交接；换装后可征求建议。走近玩家后文字询问，选择「好的」打开该伙伴库存，「稍后再说」至少 5 分钟不打扰。语音本轮暂不实现。
- **调度**：当前队伍同一时间执行一个拾取 / 售卖 / 主动提醒任务，避免争抢目标或商家。等待、离队、交战、剧情场景中的伙伴不参加。任务限同一区域的已加载人物，35 秒无法到达会取消，不传送到物品旁。玩家打开管理、交易、对话或库存界面时取消自动交接，关闭后再安排。
- 默认开启战后拾取、到店售卖、穿搭和提醒；可在进入商店前按个人或全队关闭售卖。收藏、个人规则、换装计时与丢弃物品记录随 SKSE co-save 保存；读档清理临时目标和活动队列。

## 接管范围与边界

仅管理非儿童、非敌对、非交战中的独立 NPC，剧情场景进行中暂不接管。自动衔接仅针对 Skyrim.esm 的 DialogueFollower 人类随从槽位，不扫描接管动物或独立剧情框架。对话界面关闭且状态稳定后，先验证自有别名绑定，再清理该 NPC 的原版随从别名、等待计时和计数；不调用原版解散函数，不覆盖原版脚本文件，不清理其他剧情任务别名。接管前的等待状态保留；名册满员、绑定失败或原版槽位目标发生变化时不强制释放名额。已有队友也可在详情顶部点击「纳入同行管理」，无需先解散。其他随从框架仍在运行时可能覆盖行动安排；非队友且受任务 AI 包控制的人物仍不接管。

人物名册优先显示，另读取引擎当前可枚举队友及约 60 米内人物；最多 128 人，每人最多 512 个普通法术和 512 类背包物品，玩家背包最多 512 类。异地距离显示为未知。页面在打开、手动刷新与指令完成后刷新。

伙伴库存按装备实例标识收藏与交接，保留附魔和强化数据。未带实例标识的普通装备会在原库存记录上补充标识，不增加物品数量；普通非装备物品可按堆叠数量取走。每人衣柜最多显示 512 条库存记录。收藏物品、任务物品、不可玩物品和穿戴中的装备禁止自动出售。手动取物同样保护穿戴中、任务及不可玩物品；收藏物品允许玩家主动取走。负重按全部库存含穿戴装备的重量计算，不利用穿戴免重特权。旧的基础 FormID 装备接口仍保留歧义保护，新衣柜使用实例接口。

个人居所、战斗、成长和法术设置在普通离队后保留；要彻底交还其他系统，用“释放名册”。卸载带任务与脚本的模组不作为本轮测试的一部分，测试前另存档。原版 / 自定义剧情 AI 的兼容性仍需逐人物验证。

法术书优先于普通背包物品枚举。介绍来自法术效果文本与书本正文，渲染为纯文本；效果数值使用该法术记录值，不承诺反映所有装备、perk 和动态脚本的最终加成。

## 1.1.2 修复

- 修复既有队友显示在队伍中却无法招募、无法开启任何管理操作的流程死路。接管通过原生条件检查与自有别名绑定后生效；失败回执保留未管理状态。
- 详情仅保留概览 / 行为 / 魔法。角色详情顶栏展示当前居所，并提供设置及清除入口，三个页签均可操作。
- 外层面板与装备工坊一致，固定上下 4vh、左右 3vw，无最大宽度限制。
- 日志增加未登记队友的接管资格、指令和执行结果，便于真实游戏排错。

## 1.3.0 新档布局

- 在队与离队名册共用 64 个名额；快照最多显示 128 位人物。
- 人物别名统一为 0–63，居所别名统一为 64–127；人物槽 n 的居所直接对应 n + 64。移除扩容时为旧存档保留的分段映射与兼容测试。
- 本版使用新存档。SKSE 名册格式版本更新为 2，不迁移旧布局记录；正常保存、读档和 FormID 重映射保留。
- 更新必须同时安装 DLL、ESP、PEX 和网页。已有游戏存档中的旧任务别名不属于本版支持范围。

## 1.3.1 默认成长上限

- 纳入管理及重新入队成功后，随玩家成长且原本有上限的同伴默认开启至少 300 级成长上限。原本超过 300 或无上限的角色不被降低，固定等级 NPC 不改变成长方式。
- 现有在队名册首次载入时应用一次默认值；之后手动关闭的选择会随存档保存，普通读档不会再次强行开启。重新入队会重新应用入队默认值。
- 提高的是成长上限，当前等级仍由角色的等级倍率、玩家等级等原有规则决定。

## 1.6.2 对话交换物品修复

原版 DialogueFollowerTradeTopic（00060020）要求 CurrentFollowerFaction；同行释放原版单人招募槽位后该阵营被移除，导致交易选项消失。启动时仅将这个话题中独立的正向阵营条件扩展为「原版当前随从，或属于同行管理阵营且仍是玩家队友」。等待中的同伴可交易；已解散人物不会因同行记录而获得交易资格。原有音色、人物 / 任务限制、语音、文本与 OpenInventory 脚本保留，不恢复原版招募槽位或阵营。特殊的 RemoveAllItems 响应（0002CCC5）不修改。含未知 OR 组合等第三方条件的响应保持原样，并记录跳过数量。

日志 `Follower trade dialogue restored: patched=… skipped=…` 可确认运行时修复范围。独立随从自定义的交易话题不在本次修改范围。

## 1.6.3 界面黑屏修复

游戏网页在脚本执行前即以透明底层启动，设计预览的背景只用于 demo 模式。面板本身继续使用已保存的不透明度。

MO2 在启动游戏时建立虚拟文件映射。游戏运行或启动期间不能热更新带内容哈希的新网页资源，否则入口 HTML 可能已更新而新 JS 不可见，Meridian 日志会报告 404。所有界面更新也须在 Skyrim / SKSE 完全退出后通过完整安装脚本执行，再从 MO2 重新启动；不能只覆盖运行中的 index.html。

## 1.6.4 主动询问闪退修复

负重求助和穿搭建议使用引擎创建的 MessageBoxData、明确的两项按钮数组和引用计数回调，绕过与 Skyrim 1.5.97 实际调用约定不一致的 CreateMessage 声明。拒绝排队时释放弹窗并延后重试；打开消息框期间暂停其他自主活动。点击「好的」后仍打开对应伙伴库存，「稍后再说」或取消不打开；读档或解散后忽略过期回复。

## 1.6.5 伙伴库存分类

伙伴库存使用独立分类栏：全部、武器、服装、药剂、卷轴、食物、炼金材料、书籍、钥匙、杂物。箭矢属于武器，护甲 / 衣服 / 首饰属于服装，毒药属于药剂，矿石 / 锭 / 宝石 / 灵魂石 / 金币属于杂物。依据引擎对象类型和 IsFood 标记分类，不通过名称推断。

每类显示当前搜索和锁定筛选下的物品组数，堆叠数量仍显示在卡片上。「仅看已锁定」可与任何分类组合；取物时切换分类保留已选项目，确认按全部选择计算价值和负重。原有拾取规则位掩码与锁定记录保持兼容。
